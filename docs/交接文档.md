## 2. 环境关键事实（下个会话必读）

- **本地代理**：`127.0.0.1:7890`（mihomo）必须运行；`github.com`、`auth.docker.io`、`sum.golang.org` 直连不通。
- **Docker 代理配置（两处，勿随意改）**：
  - Docker Desktop 设置 `%APPDATA%\Docker\settings-store.json`：`ProxyHTTPMode=manual` + `OverrideProxyHTTP/HTTPS=http://127.0.0.1:7890`
  - `%USERPROFILE%\.docker\daemon.json`：`proxies` 指向同一代理
- **构建前需开启代理的全局/TUN 模式**（Docker 虚拟机内 BuildKit 的直连流量要走代理），
  否则 `docker compose build` 拉基础镜像会失败；详见 部署说明.md 第 3.4 节。
- **写 Docker/系统配置务必用无 BOM 的 UTF-8**，否则 Docker Desktop 解析 JSON 崩溃（本次踩过）。
- **git 命令需要提权执行**（沙箱对 `.git` 只读）；`git status` 在沙箱内可读但 commit/push 需 escalation。
- **nginx 缓存策略（已配置，勿回退）**：`/locales/*.json` 与 `index.html` 均返回 `Cache-Control: no-cache`，保证翻译热更新与前端 chunk 不串版本。
- **入口渲染用 `createRoot`**（`apps/web/app/entry.client.tsx`）：本项目是 `ssr:false` 纯客户端应用，改回 `hydrateRoot` 会在控制台报 React #418/#423（页面仍可用但每次都报错）。
- **i18n 键源只有 en**：`keys.generated.ts` 由 `scripts/generate-types.ts` 从 `locales/en/*.json` 生成；每次 `check:types`/build 会重新生成，生成后需 `pnpm exec oxfmt packages/i18n/src/types/keys.generated.ts`。
- **ICU 插值坑**：i18next-icu 不处理 `{{name}}` 占位符。新翻译键若需嵌入链接/变量，用 `{{name}}` 占位并在组件里走 `interpolateNodes`（见 `apps/web/core/components/core/activity.tsx` 与 `issue-activity/.../helpers/i18n.tsx`）。
- **后端测试栈**：`docker compose -f docker-compose-test.yml run --rm api-tests pytest <路径>`；基础镜像用本地 tag 顶替（`python:3.12.10-alpine` → `3.12.5-alpine`），入口 `pip install` 需注入代理环境变量（`HTTP_PROXY=http://host.docker.internal:7890` 等）。
- **husky pre-commit 会失败**（hook 环境找不到 pnpm），本地提交统一用 `git commit --no-verify`（代码已过 `pnpm check`）。

## 4. 自定义开发工作流

### 改翻译（无需重建）

编辑 `packages/i18n/src/locales/<lang>/*.json` → 浏览器 Ctrl+F5（已配 no-cache，正常刷新即可）。

注意：
- **en 是键源**：新增键必须同时加到 `en/` 与目标语言文件，否则 `generate:types` 生成的类型里没有；
- 需要嵌入链接/变量的翻译，用 `{{name}}` 占位符 + `interpolateNodes`（ICU 不处理 `{{}}`，见第 2 节）；
- 改完建议跑 `pnpm --filter=@plane/i18n run build` + oxfmt 生成文件。

### 改前端/后端代码（需要重建对应镜像）

```powershell
cd D:\_Code\Server\plane

# 只改 web 前端 / i18n 包
docker compose build web && docker compose up -d web

# 只改 api 后端
docker compose build api worker beat-worker migrator && docker compose up -d api worker beat-worker migrator

# 全量
docker compose build && docker compose up -d
```

> 注意：重建前确保代理处于全局/TUN 模式（见 部署说明.md 3.4），否则 BuildKit 拉基础镜像会失败。

### 提交推送

```powershell
git add -A
git commit --no-verify -m "feat: ..."   # husky 钩子在本机找不到 pnpm，必须 --no-verify
git push origin preview
```

## 6. 注意事项 / 遗留项

- **space 容器**仍是上一版静态打包的 i18n（本会话只重建了 web）；如 space 需要热更新翻译，需重建 `docker compose build space`。

- **默认口令**：Postgres/RabbitMQ/MinIO 用的是 `.env.example` 默认值，仅限本机试用，暴露到公网前必须改。
- **数据卷**：`pgdata`/`redisdata`/`uploads`/`rabbitmq_data`，`docker compose down -v` 会清空。
- **本地提交**：本地领先 `origin/preview` 若干提交未推送（含 需求文档 v1.1、状态初始化、死代码清理），后续改动记得 `git add/commit --no-verify/push`。

- **自定义工作流已全部移除**：不要重新加面板/字段；流程推进用原生状态与 assignee。
- **i18n 生成怪癖**：`keys.generated.ts` 每次 check:types 会重新生成且不带格式，需 oxfmt（见第 2 节）。
